## 7. Implementation Notes (untuk QA)

- **API key scopes (OA-02-08)** — route didekorasi `@RequireApiKeyScopes(...)`; `POST /slack/notify` menuntut scope `slack:write`, `POST /slack/notice` menuntut `slack:notice`. Key tanpa scope yang cocok → **403**; key dengan scope `*` lolos semua. Route lain saat ini tidak menuntut scope (hanya validasi key).
- **Expiry (OA-02-10)** — `verify()` menolak key yang sudah melewati `expiresAt` → 401.
- **Slack signature (TC-01-02)** — server memverifikasi `v0=HMAC_SHA256(SLACK_SIGNING_SECRET, "v0:{timestamp}:{rawBody}")` dengan tolerance ±5 menit, memakai raw body persis (Nest `rawBody: true`). Tanpa `SLACK_SIGNING_SECRET`: di development verifikasi dilewati (ada warning), di `NODE_ENV=production` request ditolak 401.
- **Dispatch (TC-01-01)** — `POST /slack/notify|notice` membuat baris `WebhookDelivery` lalu langsung dikirim oleh engine (`WebhookService.deliverOne`, timeout 10 detik). Jika gagal, backoff 30s→2m→10m→30m→2h dijalankan cron `WebhookDeliveryCron` (per menit).
- **Env vars yang dipakai**: `SLACK_SIGNING_SECRET`, `WEBHOOK_DELIVERY_CRON`.

## 9. Implementation Notes untuk Connector (lanjutan)

- **Teams endpoint (TC-04)** — disimpan di tabel `WebhookEndpoint` yang sama dengan Slack; service memfilter URL yang mengandung `office.com`. Dispatch lewat engine OA-03 (`WebhookService.deliverOne`, event `teams.notification`) sehingga retry/backoff sama seperti Slack.
- **Google auth (TC-02)** — service account JSON + domain-wide delegation: `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_SERVICE_ACCOUNT_KEY` (PEM, boleh base64 agar aman di `.env`), `GOOGLE_ADMIN_SUBJECT`. Opsional: `GOOGLE_CALENDAR_ID` (default `primary`), `GOOGLE_ORG_UNIT_PATH` (default `/`), `GOOGLE_TIMEZONE` (default `Asia/Jakarta`). Token OAuth2 di-cache internal sampai mendekati expiry. **Keterbatasan:** kredensial Google bersifat global per deployment (satu Workspace), bukan per-tenant — `tenantId` dipakai untuk filter data & audit.
- **Directory sync (TC-02)** — hanya employee `ACTIVE`; create → jika 409 (sudah ada) otomatis di-upsert jadi update; kegagalan per-user dikumpulkan di array `failed` tanpa menghentikan batch.
- **Calendar (TC-02)** — input `start`/`end` format `YYYY-MM-DD` = all-day, selain itu diperlakukan sebagai RFC3339 datetime (dikonversi ke UTC + timezone dikirim terpisah).
- **Auto-post (TC-03)** — consumer `AccountingEventConsumer` menyimak event domain `payroll.run.approved` (di-publish `PayrollRunService.approve`); aktif hanya bila env `ACCOUNTING_AUTO_POST=true`. Kegagalan sync tidak pernah menggagalkan approve — retry manual lewat `POST /accounting-connectors/:id/sync/payroll`.
